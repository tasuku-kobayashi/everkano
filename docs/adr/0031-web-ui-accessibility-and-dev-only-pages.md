# ADR-0031: Web の UI の追補（読ませる文字の色・アクセシビリティの約束・端末の「戻る」・ホームの再読み込み・開発専用ページ）

- ステータス: 採用
- 日付: 2026-09-26
- 関連: 仕様書 §4・§5.2・H1 / [ADR-0021](0021-web-ui-implementation.md)（本 ADR で追補。`/dev/ui` の扱いは本 ADR により置き換え） /
  実装: `apps/web/app/globals.css`, `apps/web/components/ui/`（`main-shell.tsx`, `app-header.tsx`, `bottom-sheet.tsx`, `modal.tsx`, `pull-to-refresh.tsx`, `tab-bar.tsx`）,
  `apps/web/lib/navigation.ts`, `apps/web/lib/feed-refresh.ts`, `apps/web/lib/home-scroll.ts`, `apps/web/lib/text.ts`, `apps/web/next.config.ts`（`pageExtensions`）,
  `apps/web/app/(main)/dev/ui/page.dev.tsx`, `apps/web/README.md`「実装ルール」, `apps/web/e2e/layout.spec.ts`・`dark-mode.spec.ts`

## コンテキスト

納品前の検査で、ADR-0021 の方針のままでは次の問題があることが分かった。

- Instagram の青 `#0095f6` と赤 `#ff3040` をエラー文言・リンク・破壊的操作のラベルにも使っていたため、白地で 3.2:1 / 3.7:1 と
  WCAG 2.1 AA（本文 4.5:1）を満たさない文字があった（ライト・ダークとも）。
- ログイン後の画面に `<main>` ランドマークが無く、多くの画面に `h1` が無かった。ボトムシート（メモリパネル・表示名の編集）には
  スクリーンリーダーで閉じる手段が無かった。取り消せない操作（退会など）の確認ダイアログは破壊的なボタンに初期フォーカスがあり、Enter 1 回で実行された。
- Android の「戻る」ジェスチャー（`history.back`）でシート・モーダルが閉じずに画面ごと戻っていた。
- ホーム画面に追加した PWA ではブラウザの再読み込みが無く、フィードを更新する手段が無かった（Instagram はタブの再タップ・引っ張って更新）。
  タブを切り替えるとホームのスクロール位置も失われていた。
- 開発用の UI カタログ `/dev/ui` は「本番では 404 を返す」実装で、本番ビルドにもルートとチャンクが含まれていた。

## 決定

- **色**: `#0095f6` / `#ff3040`（`ig-blue` / `ig-red`）は **塗りとアイコン専用**（プライマリボタンの塗り・いいねのハート・未読バッジ）。
  読ませる文字は **`text-ig-blue-text`**（`--ig-blue-text`: ライト `#0064d1` / ダーク `#4cb5f9`）と **`text-ig-red-text`**（`--ig-red-text`: ライト `#d6001c` /
  ダーク `#ff6b77`）、トーストの操作ボタンは `--ig-toast-action` を使う（背景・シート・グレー面の上で 4.5:1 以上）。
  **プライマリボタンの白文字 × `#0095f6`（3.16:1）は、Instagram の見た目を優先した意図的な例外**（太字 15px のボタンラベル）。
  E2E `dark-mode.spec.ts`（文字のコントラスト）で、エラー文言・テキストボタン・破壊的操作がライト / ダークとも 4.5:1 以上であることを検査する。
- **ランドマークと見出し**: (main) 配下の本文は `MainShell` の `<main>` の中に置き、ページは自分で `<main>` を出さない。各画面に `h1` を 1 つ
  （`AppHeader` の title。ロゴのヘッダーは視覚的に非表示の「ホーム」、戻る + 任意の中身のヘッダーは `heading` で指定）。
- **ボトムシート**: title のあるシートには右上に「閉じる」ボタンを出す（最下段に「キャンセル」行があるシートだけ省略してよい）。
- **確認ダイアログ**: 取り消せない操作（退会・記憶の削除など）の確認は「キャンセル」に初期フォーカスを置く。
- **端末の「戻る」**: シート・モーダルを開くと履歴を 1 つ積み、端末の「戻る」はまずそれを閉じる（`lib/navigation.ts`）。UI で閉じた後の「戻る」は前の画面へ戻る。
- **ホームの再読み込み**: 先頭で Home タブ・ロゴを再タップ、または下に 64px 以上引っ張ると、フィードを 1 ページ目から取り直す（`lib/feed-refresh.ts`・
  `pull-to-refresh.tsx`）。5 分以上バックグラウンドにいた後に先頭で復帰したときも取り直す。ブラウザ標準の引っ張って再読み込み（ページ全体の再読み込み）は
  `body` の `overscroll-behavior-y: none` で止め、この実装に置き換える。別のタブから Home タブで戻ると、読んでいた位置から表示する（`lib/home-scroll.ts`）。
- **表示名の頭文字**: アバターの頭文字は絵文字（サロゲートペア・結合文字）を壊さずに 1 文字を取る（`lib/text.ts`）。
- **開発専用のページは `page.dev.tsx`** と名付ける。`next.config.ts` の `pageExtensions` を `next dev` のときだけ `dev.tsx` を含むようにし、
  **本番ビルドにはルートもチャンクも含めない**（`/dev/ui` は `next dev` のときだけ存在する）。ADR-0021 の「`/dev/ui`（本番ビルドでは 404）」を置き換える。

## 結果・トレードオフ

- 読ませる文字は AA を満たす。青・赤の文字の色は Instagram より少し濃い（ライト）/ 明るい（ダーク）。
- プライマリボタンのラベルだけは AA（4.5:1）を満たさない（大きな文字の基準 3:1 は満たす）。ブランドの見た目との判断で、変える場合はこの ADR を置き換える。
- 端末の「戻る」の履歴を積むため、シートを開いたまま画面遷移したときの履歴の扱いに注意が要る（`lib/navigation.ts` と E2E `layout.spec.ts` で検査）。
- 独自の引っ張って更新はホームのフィードだけ。他の画面では引っ張っても何も起きない（標準の再読み込みも止めているため）。
- 開発用のページを本番に出さない仕組みが「ファイル名の規則」になった。`page.dev.tsx` 以外の名前で開発用ページを作ると本番に出るので、レビューで確認する。

## 代替案

- **Instagram の青・赤を文字にも使い続ける**: 見た目は近いが、エラー文言や破壊的操作が読みにくい利用者がいる。DD のアクセシビリティ確認でも指摘される。
- **プライマリボタンも濃い青にする**: AA は満たすが、Instagram の見た目から離れる（依頼の最優先事項は「Instagram の忠実な再現」）。
- **`/dev/ui` を環境変数で無効化する**: 本番ビルドにコードが残り、設定の誤りで公開され得る。ビルドから外す方が確実。
- **ブラウザ標準の引っ張って再読み込みを残す**: ページ全体の再読み込みになり、スクロール位置・キャッシュが失われる。iOS のホーム画面の PWA では使えない。
